# 도메인 문서

> **코드를 읽어도 알 수 없는 것만 적는다.**
> 컴포넌트 목록 · 필드 목록 · 디렉토리 트리는 **적지 않는다** — 타입 정의 · 코드가 진실이다.
> 여기 담기는 건 **불변식**(깨지면 버그인 규칙), **함정**(실제로 물렸던 것), **상태 전이**다.

## 왜 도메인별인가

문서를 *타입*으로 나누면(가이드 / 핸드북 / 레퍼런스 …) 코드의 *도메인* 경계와 축이 어긋난다.
도메인 하나를 고쳤을 때 여러 문서로 파편이 튀고, 그게 문서 잔손질의 절반이다.
그래서 이 디렉토리의 파일 목록은 **코드 경계와 1:1로** 맞춘다.

## 파일 이름 규칙

소유 코드의 디렉토리명을 그대로 쓴다 — `src/features/typing-effect/` → `typing-effect.md`.

## 새 도메인 문서를 쓸 때

[`_template.md`](_template.md)를 복사한다. 7섹션 고정이다.

- **§3 불변식과 §4 함정이 이 문서의 존재 이유다.** 나머지는 거들 뿐이다
- 불변식은 "깨지면 버그"인 것만. 코딩 스타일 권장사항은 [`AGENTS.md`](../../AGENTS.md)로 간다
- 함정은 **실제로 물렸던 것**만. 상상한 위험은 적지 않는다
- 코드에서 바로 읽히는 건 §7 "여기 없는 것"에 어디를 보라고만 적는다
- 문서를 추가하면 위 지도에 한 줄 더한다
